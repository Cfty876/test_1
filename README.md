# Движение Первых — Совет Екатеринбурга

Публичная платформа инициатив Совета Первых Екатеринбурга и кабинеты команды.

## Локальный запуск

Требуется Node.js.

1. Выполнить `npm install`.
2. Создать администратора командой `npm run setup:admin` и сохранить выведенный пароль.
3. Запустить сайт командой `npm run dev`.

## Подготовка публикации на Vercel

Проект собран на Vite. Конфигурация `vercel.json` задаёт сборку и каталог `dist`; функции API расположены в `api/`.

1. Создать репозиторий Git и загрузить туда файлы проекта. Не добавлять `.env.local`, `.vercel/` и секреты.
2. Импортировать репозиторий в Vercel; Framework Preset должен определиться как Vite.
3. Используйте Node.js 24.x. Он соответствует требованиям Vite 8 и доступен как runtime для сборок и функций Vercel.
4. Создайте отдельные Blob Stores для публичной доски и закрытой базы; закрытые хранилища должны иметь тип **Private**. Для Preview используйте отдельные хранилища, не используйте Production-хранилища.
5. Подключите каждый store к проекту через Vercel Storage с OIDC:
   - публичная Production-доска — префикс переменных `BLOB_PRODUCTION`;
   - публичная Preview-доска — `BLOB_PREVIEW`;
   - закрытая Production-база — `PRIVATE_BLOB_PRODUCTION`;
   - закрытая Preview-база — `PRIVATE_BLOB_PREVIEW`.
   Ограничьте каждый store соответствующим окружением. Подключение создаст `*_STORE_ID`; Vercel выдаёт runtime OIDC credentials автоматически.
6. Задайте серверные переменные `AUTH_USERNAME`, `AUTH_DISPLAY_NAME`, `AUTH_ROLE=admin`, `AUTH_PASSWORD_SALT`, `AUTH_PASSWORD_HASH`, `AUTH_SESSION_SECRET` отдельно для Production и Preview. Установите `AUTH_COOKIE_SECURE=true`.
7. Не меняйте production `AUTH_SESSION_SECRET`: он подписывает сессии и шифрует существующую базу. При первом запросе Production старая база переносится в private store; прежний зашифрованный Blob удаляется после успешного переноса. Если старая база находится в отдельном публичном store, задайте `LEGACY_BLOB_STORE_ID` в Production.
8. Запустите деплой. Изменения переменных окружения применяются при следующем деплое.

В Vercel Blob список одобренных инициатив хранится публично, а закрытая база — в private Blob Store и дополнительно шифруется перед записью. Production и Preview используют разные пути данных; закрытая база также должна находиться в разных хранилищах для этих окружений. Для локальной разработки используется файл `data/platform-state.json`, исключённый из Git.

Публикация инициатив доступна только администратору с действующей сессией. Председатель получает базу, но не заявки и управление пользователями; партнёр видит только адресованные ему инициативы. Публичная доска получает только название, описание, направление, имя автора и дату; телефон и почта не передаются.

## Подборка на главной странице

В кабинете администратора и председателя есть вкладка «Главная страница». Организатор выбирает до трёх уже опубликованных инициатив, заполняет запрос на помощь для каждой и задаёт порядок карточек. Подборка появляется в блоке «Нужны единомышленники». Можно сохранить меньше трёх карточек или очистить подборку целиком.

Настройки сохраняются в зашифрованной базе платформы. Публичный `GET /api/platform/homepage` возвращает только опубликованные карточки с запросом на помощь; изменение через `POST` разрешено администратору и председателю. Отклики через «Хочу помочь» связаны с исходной инициативой и видны в заявках и базе.

При принятии заявки публикация выполняется на сервере; сбой публикации оставляет заявку доступной для повторной обработки. Локальная и production-доски используют общий обработчик и отдельные хранилища для каждого окружения.

## Проверки

- `npm run lint` — проверка TypeScript.
- `npm run build` — production-сборка.
- `node --import tsx --test server/platformApi.test.ts src/utils/auth.test.ts` — проверки публикации, прав доступа, подборки, откликов и конкурентного локального сохранения. Тесты создают отдельную временную базу и удаляют её после завершения.
