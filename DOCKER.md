# PostgreSQL и Docker для Первика

## Запуск

Из корня проекта:

```powershell
npm run db:setup
npm run db:up
npm run db:import
npm run dev
```

`db:setup` создаёт случайный пароль PostgreSQL в игнорируемом `.env.docker.local` и отдельный файл авторизации контейнера `.env.docker-app.local`. Существующие реквизиты PostgreSQL сохраняются. Локальный администратор должен быть настроен заранее.

`db:import` переносит всю существующую локальную базу и локальные фотографии. Перед переносом создаётся копия исходных файлов и настроек в `data/backups/`. Затем два документа и файлы записываются в одной транзакции. Прочитанные обратно данные сравниваются с источником; только после совпадения `DATABASE_URL` записывается в `.env.local`. Перезапустите dev-сервер, чтобы он перечитал переменные. Повторный импорт в заполненную базу останавливается и ничего не заменяет.

Обычный запуск после первого импорта:

```powershell
npm run db:up
npm run dev
```

## Весь сайт в контейнере

```powershell
npm run docker:up
```

Сайт и API доступны по `http://localhost:3001`, PostgreSQL — `127.0.0.1:54329`. Порт базы и сайт контейнера привязаны только к локальному компьютеру. Dockerfile собирает интерфейс и запускает Express с теми же обработчиками API, что использует локальная разработка. Секреты не попадают в образ.

## Управление и копии

- `npm run db:status` — состояние контейнеров.
- `npm run db:inspect` — количество записей каждого типа и фотографий без раскрытия контактов.
- `npm run db:backup` — полный PostgreSQL dump и закрытая копия конфигурации рядом с ним в `data/backups/`.
- `npm run db:stop` — остановить контейнеры с сохранением данных.

Для восстановления используйте `pg_restore` в новую пустую базу и сохранённую конфигурацию. Ключ `AUTH_SESSION_SECRET` нужен для расшифровки закрытых записей. Файлы `.env`, дампы и копии не отправляются в GitHub или браузер.

## Устройство хранилища

PostgreSQL 17 хранит полный текущий формат платформы: заявки, историю решений и коды отслеживания (хеши), активистов, аккаунты (соли и хеши паролей), передачи партнёрам, подборку главной, реализации, отчёты, уведомления и лайки. Закрытое состояние сохраняет AES-256-GCM шифрование. Публичная доска хранится отдельно, бинарные фотографии — в `platform_files`.

Таблица `platform_documents` содержит версию и время обновления документа. Изменения выполняются транзакционно с блокировкой строки; параллельные действия не затирают друг друга. Схема есть в `docker/schema.sql`; сервер применяет её идемпотентно. Постоянный том — `pervik_pervik_postgres`.

При наличии `DATABASE_URL` сервер использует PostgreSQL. Без него прежние файл и Vercel Blob продолжают работать. Docker на локальном компьютере не является доступной извне базой для Vercel: production подключается к отдельному доступному серверу PostgreSQL через собственный `DATABASE_URL`. Настройки Vercel этой задачей не меняются.
