# Движение Первых — Совет Екатеринбурга

Публичная платформа инициатив Совета Первых Екатеринбурга и кабинеты команды.

## Локальный запуск

Требуется Node.js.

1. Выполнить `npm install`.
2. Создать администратора командой `npm run setup:admin` и сохранить выведенный пароль.
3. Запустить сайт командой `npm run dev`.

## Подготовка публикации на Vercel

Проект собран на Vite. Конфигурация `vercel.json` задаёт сборку и каталог `dist`; функции API расположены в `api/`.

1. Создать репозиторий Git и загрузить туда файлы проекта. Не добавлять `.env.local`, `.vercel/` и секреты.
2. Импортировать репозиторий в Vercel; Framework Preset должен определиться как Vite.
3. Подключить к проекту Vercel Blob Store и убедиться, что в Production Variables доступен `BLOB_READ_WRITE_TOKEN`.
4. Добавить серверные переменные `AUTH_USERNAME`, `AUTH_DISPLAY_NAME`, `AUTH_ROLE=admin`, `AUTH_PASSWORD_SALT`, `AUTH_PASSWORD_HASH`, `AUTH_SESSION_SECRET` из защищённой локальной конфигурации администратора. Установить `AUTH_COOKIE_SECURE=true`.
5. Не менять `AUTH_SESSION_SECRET` без миграции данных: он используется для защиты сессий и шифрования закрытой базы.
6. Запустить деплой. Изменения переменных окружения применяются при следующем деплое.

На Vercel список одобренных инициатив хранится в Vercel Blob по пути `pervik/public-initiatives.json`. Заявки, контакты, доступы и сообщения партнёрам хранятся отдельным зашифрованным снимком `pervik/private-platform-state.enc`; в открытом Blob Store находится только шифротекст. Для локальной разработки используется файл `data/platform-state.json`, исключённый из Git.

Публикация инициатив доступна только администратору с действующей сессией. Председатель получает базу, но не заявки и управление пользователями; партнёр видит только адресованные ему инициативы. Публичная доска получает только название, описание, направление, имя автора и дату; телефон и почта не передаются.
