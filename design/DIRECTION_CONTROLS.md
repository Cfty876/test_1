# Единые направления в анкетах и кабинетах

1 ноября 2026.

## Поведение

- Инициативы и активисты используют общий `DirectionPicker`: одинаковая сетка, типографика, подписи, выделение и фокус. Для инициативы выбирается одна тема, для активиста — один или несколько навыков помощи. На узком экране карточки идут одной колонкой; зоны нажатия не меньше 44px.
- Навыки активиста выбираются явно. Такой же выбор доступен при отклике на конкретный проект. Сервер сохраняет выбранные навыки, не заменяя их темой проекта.
- В очереди заявок все направления человека видны отдельными метками сразу, до раскрытия контактов и описания. В деталях используются те же метки. Названия переносятся, не обрезаются и не скрываются за `+N`.
- В базе участников и идей есть кнопки направлений со счётчиками. Числа учитывают текущий поисковый запрос; счётчик «Все» означает число записей, а не сумму направлений. Один человек может относиться к нескольким направлениям, что объяснено рядом с фильтрами.
- Поиск понимает названия и пояснения направлений, включая написание без «ё». Запрос сохраняется при переключении базы между участниками и идеями; фильтр направления сбрасывается, чтобы не смешивать два разных набора.
- В очереди заявок фильтр направлений раскрывается отдельно, чтобы не перегружать экран. Он работает вместе со статусом, поиском, форматом заявки и выбранной реализацией. Специалист видит счётчик найденных записей.
- Школьный каталог также использует общие метки и фильтры. Темы инициатив и навыки помощи остаются разными данными.
- Старый основной тип участника используется только при отсутствии массива выбранных навыков. Дубли навыков не завышают счётчики; существующие инициативы без темы отмечаются как требующие уточнения.

## Реализация и проверка

Общие компоненты: `src/components/DirectionControls.tsx`; данные и функции для просмотра: `src/utils/participantDirections.ts`; оформление: `src/directions.css`. Дополнительные библиотеки и запросы к API не добавлены. Подсчёт и фильтрация выполняются на уже загруженных данных, дорогие выборки мемоизированы. Права доступа и структура хранения не изменены.

Проверены типы, production-сборка, 20 проверок локального API/защиты и 15 сценариев с PostgreSQL. Дополнительно проверены многозначные навыки, отсутствие повторного подсчёта, приоритет выбранных навыков над устаревшим основным типом, раздельность тем/навыков и HTML-разметка двух видов выбора, очереди, базы и школьного каталога через React SSR. SSR не подтверждает пиксельную вёрстку.

Браузерный инструмент недоступен: ошибка записи kernel assets Windows. Визуальная проверка в реальном браузере не подтверждена. При первом просмотре стоит проверить обе анкеты на телефоне, метки человека с несколькими навыками и сочетание поиска с фильтром.

Использованы локальные рекомендации UI UX Pro Max (перенос меток, контекстные счётчики, статические значения отдельно от действий), Taste/app screens и React Best Practices. Сохранены Pervye Extended Bold / Pervye Book и красно-белая идентичность. Новые анимации не добавлены. Каталог 21st просмотрен на уровне метаданных: [Choicebox, halaska-studio](https://21st.dev/@halaska-studio/components/choicebox), [Radio Group in Card with Separators, sean0205](https://21st.dev/@sean0205/components/c-radio-group-8); чужой код не получался. Реализация самостоятельная, на существующей системе компонентов.
